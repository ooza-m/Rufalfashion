# Rufal catalog and finance behavior

The Salla product editor reference supplied by the owner informed the tabbed workflow: basic bilingual details, ordered primary/detail photos with bilingual ALT, descriptions with safe Markdown formatting, arbitrary options, independent variant inventory/prices, timed discounts, barcode, weight, publication status and search metadata. Source: https://help.salla.sa/article/إضافة-منتج-ملموس-جاهز/j26383gile80wtexu77744u9 and https://help.salla.sa/article/أدر-منتجاتك-باحترافية/imx7rasv8181o7v9r6tumsmx .

Inventory movements record both physical and reserved deltas. Reservations occur atomically on order creation, not when a piece is added to a browser cart. Payment confirmation converts reserved stock to a verified sale; unpaid cancellation/expiry releases only the reservation. Reference for separated inventory states and movement records: https://help.salla.sa/article/إدارة-وجرد-المخزون/xzpw5e46wflnxg611caz0aem . Rufal's payment deadline remains the owner's approved 48 hours from actual link sending.

The code convention is preserved as style+color+two-digit year, length+sleeve, supplier code, global sequence. The owner explicitly confirmed LM means long dress / medium sleeve. Existing codes must remain unchanged. The server allocates a sequence, then locks classification fields after creation. Variant suffix V001/V002 distinguishes arbitrary options without changing the base piece identity. Similarity uses these classifications and categories/tags, not the identity or purchase cost of the supplier.

The financial report separates product revenue, delivery revenue, cost of goods sold, actual carrier cost, actual payment fees/tax and operating expenses. Unknown cost components stay null. Gross margin uses (selling price - cost) / selling price; target-price calculation uses cost / (1 - margin). Actual sale costs are snapshotted on order lines. This reflects the distinction between recorded costs and incomplete profit reports described at https://help.shopify.com/ar/manual/reports-and-analytics/shopify-reports/report-types/default-reports/profit-reports . Reports do not infer an actual bank balance and do not treat financing or inventory purchases as operating expenses.

Frontend calculators and field previews work without a connection. Shared records, publication, authenticated financial data, payment reconciliation and order intake remain server-backed and gated by activation. No Salla-specific channel, external taxonomy or integration is presented as connected. Customer reviews are a future verified-purchase feature; no synthetic reviews are displayed. Financial history import, purchase-batch cost allocation, refund/return reconciliation, granular editable team management and network-dependent end-to-end verification are subsequent tasks.

Quality checks: 12 domain/security tests, syntax, bilingual copy keys, asset/local-link verification, transparent assets and HTML nesting. Migration and stock/settlement constraints were checked on an isolated Neon branch with rolled-back fixtures. Browser rendering and live owner/staff account flows have not been verified in this environment.

An additional DOM interaction check exercised arbitrary numeric sizes plus color combinations, margin-based pricing, live product name preview, disabled shared writes before activation, product gallery presence, quantity controls, modal menu state and font/density sanitization. It caught and fixed a form-control naming collision (`length` vs `HTMLFormControlsCollection.length`). These checks validate behavior, not rendered layout on Safari/iPad.
